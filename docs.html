1. In-Browser OCR Architecture & Zero-Storage Security

Visiolog is designed with a strict zero-retention, client-side first architecture. Document transcription runs entirely in your web browser without routing document images through proprietary backend proxies:

  • Client-Side Canvas Downsampling: When you select or drop high-resolution documents (e.g. 48MP smartphone photos), the browser HTML5 Canvas engine scales the image proportionally to a maximum dimension of 2048px before encoding to JPEG Base64. This downsampling maintains OCR character fidelity while minimizing latency and memory overhead.
  • Direct Provider REST Dispatch: API calls connect directly from your browser to your selected AI vision endpoint (Google Generative Language API, OpenRouter, local Ollama, or private inference servers).
  • Volatile Memory Buffer: Image byte arrays and canvas bitmaps reside exclusively in volatile browser RAM and are purged immediately when a new document is loaded or the tab is closed.

2. AI Vision Providers & Multi-Model Combobox

Configure your AI vision engine on the Settings page. Visiolog supports four adaptable provider modes:

A. Google Gemini (Default)

Connects directly to the Google Generative Language REST API. Provide your Gemini API key and click Auto-Detect Models to dynamically retrieve active models (such as gemini-2.5-flash, gemini-2.5-pro, and gemini-1.5-flash).

B. OpenRouter

Enables access to open-weights multimodal vision architectures via OpenRouter. Supported presets include meta-llama/llama-3.2-11b-vision-instruct, qwen/qwen-2.5-vl-72b-instruct, and anthropic/claude-3.5-sonnet.

C. Ollama (Local Private Inference)

Execute OCR completely offline on your local GPU with zero API keys. Run Ollama locally on port 11434 with cross-origin resource sharing enabled:

# Enable cross-origin access for web browser execution
export OLLAMA_ORIGINS="*"
ollama run llama3.2-vision

D. Custom Endpoint (OpenAI-Compatible)

Connect to any self-hosted inference server (vLLM, LM Studio, Together AI, or local gateway). Specify the Base URL (e.g. http://localhost:8000/v1), optional Bearer token, and model identifier.

3. Outbound Connection Verification & Diagnostics

Under Step 3 in Settings, the Test Outbound Connection engine performs live network and credential probing before running extraction workloads:

  • Verification Check: Sends a lightweight diagnostic ping to the provider endpoint with your specified model identifier and credentials.
  • Green Verified Badge: Indicates successful network handshake, valid authorization, and active model availability along with exact measured round-trip latency (e.g. 142ms).
  • Red Diagnostic Diagnostic: Displays targeted troubleshooting guidance indicating whether an error stems from an invalid API key, model deprecation, network timeout, or CORS origin restriction.

4. Dual Rendering Engine: Table & Notes View

The Workspace provides dual synchronized rendering modes tailored for diverse data analysis workflows:

  • Table View (Interactive Spreadsheet):
    • Full contenteditable cell modification with keyboard navigation.
    • Dynamic row creation via the + Row toolbar button.
    • Header renaming with live column calculation.
    • Standard RFC 4180 CSV export formatted for immediate Excel and Google Sheets ingestion.
  • Notes View (Structured Document):
    • Transforms tabular records into human-readable Markdown and HTML summaries with section headers and bulleted fields.
    • Includes one-click clipboard copy and direct Markdown (.md) file export.
    • Editable text buffer allows appending custom analyst observations and audit notes.

5. Multi-File Queue Management & In-Memory Retry

Visiolog streamlines multi-document ingestion through client-side queue buffers:

  • Multi-Document Ingestion: Select multiple photos or scanned files simultaneously. A visual queue list appears in the sidebar allowing seamless switching between documents.
  • In-Memory Image Retention: The uploaded image data remains stored in client RAM during extraction. If a provider rate limit (HTTP 429) or token expiration occurs, the document is not lost.
  • Instant Retry Action: Click the visible Retry Conversion button or adjust settings in Settings to immediately re-run OCR without having to locate and re-upload your image file.
  • Exponential Backoff: Automatic client-side retry handling (1s, 2s, 4s delays) resolves transient rate limits automatically.

6. Local Storage Schema & Export Formats

All application state, user preferences, and conversion history are persisted locally in localStorage:

Storage Key Data Type Description
visiolog_theme String ('light' | 'dark') User color theme preference.
visiolog_provider String ('gemini' | 'openrouter' | 'ollama' | 'custom') Active AI vision inference engine.
visiolog_model String Active vision model identifier.
visiolog_demo_gemini_key String Google Gemini API key.
visiolog_demo_openrouter_key String OpenRouter API key.
visiolog_custom_endpoint String Base URL for OpenAI-compatible endpoint.
visiolog_workspace_history JSON Array Last 20 converted document records with timestamps.

7. Keyboard Navigation & Grid Shortcuts

Operate the workspace grid efficiently using standard keyboard shortcuts:

  • Tab / Shift + Tab: Navigate to next / previous cell in row.
  • Enter: Commit cell edit and move down to the next row.
  • Escape: Discard active cell edit and restore original text value.

8. Diagnostics, Troubleshooting & Support

If you encounter unexpected errors during extraction:

  • HTTP 400 (Bad Request): Verify that the model specified supports vision/multimodal generation methods.
  • HTTP 403 / 401 (Unauthorized): Check that your API key is correctly typed and active in Settings.
  • CORS Connection Blocked (Ollama / Local Server): Ensure your local server was started with OLLAMA_ORIGINS="*".
